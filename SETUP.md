# Setup

This boilerplate ships with `example_app` as the demo application. When you
clone it to start your own project, you rename that app and update a few
identifiers so nothing references the template's originals.

Two ways to do it: **automated** (recommended) or **manual**.

---

## Prerequisites

- Flutter 3.27+ and Dart 3.6+
- Melos: `dart pub global activate melos`
- The repo cloned and open at its root directory

**Before you start:** commit the pristine state so you can diff afterward.

```bash
git add .
git commit -m "chore: pristine template"
```

After running setup, run `git diff` to review exactly what changed.

---

## Automated setup

```bash
dart run tool/setup.dart
```

The script prompts for three values:

| Prompt | Example | Rules |
|---|---|---|
| App display name | `My App` | Free text, shown to users in the launcher |
| App slug | `my_app` | `snake_case`, starts with a letter, only lowercase + digits + underscores |
| Organization identifier | `com.mycompany` | Dotted lowercase, reverse-DNS style |

What the script does:

1. Renames `apps/example_app/` → `apps/<slug>/`
2. Rewrites `example_app` → `<slug>` in Dart files, pubspecs, `melos.yaml`, workflows
3. Rewrites `ExampleApp` → `<PascalCase(slug)>` across all Dart files
4. Rewrites `Example App` → `<display_name>` across all config and source files
5. Rewrites `com.example.flutter_monorepo_boilerplate` → `<org>.<slug>` (Android)
6. Rewrites `com.example.flutterMonorepoBoilerplate` → `<org>.<camelCase(slug)>` (iOS)
7. Rewrites `com.example` → `<org>` for any remaining occurrences
8. Updates the root `pubspec.yaml` workspace list and `melos.yaml`
9. Deletes the stale `pubspec.lock` (regenerated by `melos bootstrap`)

After it finishes:

```bash
melos bootstrap
melos run analyze
melos run test
cd apps/<slug> && flutter run
```

> **If something looks wrong:** `git checkout .` and `git clean -fd` revert
> everything. Then use the manual steps below.

## Manual setup

Use these steps if you prefer full visibility, or if the script exits partway.

### 1. Rename the app folder

```bash
git mv apps/example_app apps/my_app
```

### 2. Update the app pubspec

`apps/my_app/pubspec.yaml`:

```yaml
name: my_app          # was: example_app
```

### 3. Update the root workspace list

Root `pubspec.yaml`:

```yaml
workspace:
  - apps/my_app       # was: apps/example_app
  - packages/core
  # … rest unchanged
```

### 4. Check melos.yaml

`melos.yaml` uses `apps/**` as a glob — it picks up the renamed folder
automatically. Verify the `name:` field at the top if you want to change the
monorepo name too.

### 5. Find-replace across source files

**macOS / Linux:**

```bash
# Package name + imports
grep -rl 'example_app' \
  --include='*.dart' --include='*.yaml' --include='*.yml' \
  --include='*.json' --include='*.md' . \
  | grep -Ev '(\.dart_tool|/build/)' \
  | xargs sed -i '' 's/example_app/my_app/g'

# Root widget class
grep -rl 'ExampleApp' \
  --include='*.dart' --include='*.yaml' . \
  | grep -Ev '(\.dart_tool|/build/)' \
  | xargs sed -i '' 's/ExampleApp/MyApp/g'

# Display name
grep -rl 'Example App' \
  --include='*.dart' --include='*.plist' --include='*.xml' . \
  | grep -Ev '(\.dart_tool|/build/)' \
  | xargs sed -i '' 's/Example App/My App/g'
```

**Windows PowerShell:**

```powershell
$files = Get-ChildItem -Recurse -File `
  -Include *.dart,*.yaml,*.yml,*.json,*.md,*.plist,*.xml `
  | Where-Object { $_.FullName -notmatch '\.dart_tool|\\build\\' }

foreach ($f in $files) {
  $c = Get-Content $f.FullName -Raw
  $c = $c -replace 'example_app', 'my_app' `
           -replace 'ExampleApp',  'MyApp' `
           -replace 'Example App', 'My App'
  Set-Content $f.FullName $c
}
```

### 6. Android identifiers

`apps/my_app/android/app/build.gradle.kts`:

```kotlin
android {
    namespace = "com.mycompany.my_app"          // was: com.example.flutter_monorepo_boilerplate
    defaultConfig {
        applicationId = "com.mycompany.my_app"  // was: com.example.flutter_monorepo_boilerplate
    }
}
```

Replace `com.example` with your org. The suffix is typically `<slug>` in
snake_case.

### 7. iOS identifiers

In `apps/my_app/ios/Runner.xcodeproj/project.pbxproj`, replace every occurrence
of:

```
com.example.flutterMonorepoBoilerplate
```

with:

```
com.mycompany.myApp
```

The `.RunnerTests` suffix variant (`com.example.flutterMonorepoBoilerplate.RunnerTests`)
becomes `com.mycompany.myApp.RunnerTests`.

Then open the project in Xcode
(`apps/my_app/ios/Runner.xcworkspace`):

- **Runner target → General → Display Name** → set your display name
- **Runner target → General → Bundle Identifier** → confirm it matches above
- **Runner target → Signing & Capabilities → Team** → select your Apple team

### 8. Regenerate the lock file

```bash
rm pubspec.lock          # or: del pubspec.lock on Windows
melos bootstrap
```

### 9. Verify

```bash
melos run analyze
melos run test
cd apps/my_app && flutter run
```

## When not to rename

If you want to keep `example_app` as a reference demo and add your own app
alongside it:

```bash
flutter create apps/my_app --org com.mycompany
```

Add `apps/my_app` to the root `pubspec.yaml` workspace list, add path
dependencies on each shared package in `apps/my_app/pubspec.yaml`, then run
`melos bootstrap`. This is the safer choice if you are evaluating the
boilerplate rather than fully adopting it.

---

## Adding your own packages

```bash
mkdir -p packages/my_package/lib/src
```

Create `pubspec.yaml`, `lib/my_package.dart`, `test/`, and an
`analysis_options.yaml` that inherits the root ruleset:

```yaml
include: ../../analysis_options.yaml
```

Add the new package path to the root `pubspec.yaml` workspace list, then
`melos bootstrap`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `melos bootstrap` fails after rename | `rm pubspec.lock` and rerun |
| iOS build fails on bundle ID | Open Xcode, set Team + Bundle Identifier in the Runner target |
| Android build fails on namespace | Check `android/app/build.gradle.kts` — `namespace` and `applicationId` must match |
| Imports fail in the IDE | Restart the IDE; run `dart pub global run melos bootstrap` from the root |
| Setup script exited partway | `git checkout . && git clean -fd`, then use the manual steps above |
| `package:example_app` still appears in analysis | Run `melos run analyze` — if errors remain, grep for `example_app` in `*.dart` files |

## What the setup script does NOT do

These require a human decision and cannot be automated safely:

- **iOS code signing** — pick your Apple team in Xcode.
- **Android signing keys** — configure `android/key.properties` for release
  builds. Never commit this file.
- **App icons** — replace `assets/` and native icon files per platform.
- **Firebase / cloud config** — `google-services.json`,
  `GoogleService-Info.plist`, etc. Add only if you use Firebase.
- **Store metadata** — app store listings, privacy policies, screenshots.
- **CI secrets** — update any GitHub Actions secrets or environment variables
  that reference the old app or org name.
